# Flapp

Flapp is a Flash Player generated by Claude Code from the Flash specification documents.
It runs in JavaScript.

# Features

It loads SWF files and plays them on a browser Canvas. It has no dependent packages.

- **Files**: uncompressed SWF (FWS), zlib-compressed SWF (CWS), and LZMA-compressed SWF (ZWS)
- **Display**: shapes (solid, gradient, and bitmap fills and lines), bitmaps, morph shapes, text (static text and text fields, with per-range formats, `htmlText` format tags, bullets, and word wrap),
  buttons, masks, blend modes, 9-slice scaling, scenes, filters (blur, drop shadow, glow, bevel, gradient glow, gradient bevel, color matrix, convolution, and displacement map),
  3D transforms (AS3 `z`, `rotationX` / `rotationY`, `Matrix3D`, and perspective projection)
- **Scripts**: ActionScript 1 / 2 (AVM1) and ActionScript 3 (AVM2)
- **Sound**: event sounds and stream sounds (PCM, ADPCM, MP3)
- **Video**: video embedded in a SWF and FLV files (Sorenson H.263, Screen Video, VP6, and VP6 with alpha; Screen Video v2 for FLV as well.
  In the browser, H.264 and AAC too)
- **Input**: mouse and keyboard

A SWF is treated as an untrusted input when `trust` is unset or 0 (the default).

- Scripts are run by interpreting one instruction at a time. `eval` and code generation are not used.
- There are limits on the instruction count, the allocation count, the call depth, the number of display objects, the number of bitmap pixels, and so on.
- The player does not do any network access or page navigation by itself. Requests such as `getURL` and `URLLoader` are recorded.
  Navigation and loading are left to the function the host passes as the `network` option of `Movie.load`. When `trust` is 0, `network` is not passed, so nothing happens
  (for loading, the script is told that it failed).

When `trust` is set (`?trust` alone, or `trust=1`), the SWF is treated as a trusted SWF, and Flapp aims to behave as the real player does. On a browser page, `network` is passed,
which allows page navigation and loading from the script (see "Playing in the browser" below). For now, `trust` changes only this point,
and the execution limits above still apply when the SWF is trusted.

Not supported:

- The palette inside a Screen Video v2 stream (the real player cannot play it either)
- The pixels of a loaded image can be read only when the host passes `decodeImage` (in the browser, the image decoder). The pixel values of a JPEG differ slightly
  from the real player, because the decoders differ
- Scripts of ActionScript 1 / 2 SWFs loaded with `Loader` (they are shown only), separation of `ApplicationDomain` in AS3 (a loaded SWF's
  classes are always treated as children of the loading domain), and the per-version script rules when an AS1 / 2 SWF of a different version is loaded
- AVM2 bytecode verification (VerifyError) is not done. When a missing class is referenced, the error is found while the code runs, so the exception can differ from the real player
  (the real player gives #1014 when it defines a class whose parent class is missing; Flapp gives #1065 during the class's initialization).
- Stage3D, RTMP / RTMFP, DRM, Pixel Bender, TLF, camera and microphone, printing, Worker
- Nellymoser and Speex sound
- Of text field input, right-to-left text is shown in reordered form, but reordering across a format change within one line, and the caret and selection positions (kept in string order), are not supported. The caret position set by clicking is measured with the device font's widths, so it can be about one character off from the real player
- Of `<img>` tags, a `src` that points to a library clip or a SWF (JPEG, PNG, and GIF URLs are loaded with `network.load`, and library bitmaps are drawn by their export name or class name), `align` values other than `left` and `right`, and `getImageReference`
- Link state styles such as `a:hover` (`StyleSheet` can be attached with `TextField.styleSheet` in both AS2 and AS3)
- Among 3D transforms: filters, blend modes, masks, `scrollRect`, and 9-slice scaling inside a 3D subtree; `getBounds` of 3D objects; and `Matrix3D.pointAt` (not the same values as the real player)
- `ShaderFilter`. `BitmapData`'s `perlinNoise` and `pixelDissolve` do not give the same values, because their random sequences differ from the real player. The blur-type `applyFilter` results differ slightly from the real player in the semi-transparent values outside the edges

# Usage

Node.js (tested with 22) and a browser are required.

## Embedding a SWF in a page

You can place a SWF directly in a page with the `<flapp-player>` element (it replaces Flash's `<embed>`).
It loads ES modules, so serve it over http, not as a file (`npm run serve` also works).

```html
<script type="module" src="web/flapp.js"></script>
<flapp-player src="movie.swf"></flapp-player>
```

- Attributes: `src` (the SWF URL), `trust` (when present, the SWF is played as a trusted SWF; when absent, it does no network access and no page navigation; see "Playing in the browser" below),
  `encoding` (the character encoding for SWF 5 and earlier; by default it is chosen from the browser's language), and `match-player` (do not show what the real player does not show).
  Changing `src` or `trust` loads the SWF again.
- With `trust`, network access can be narrowed with these attributes (when omitted, all are allowed, as in the real player):
  - `allow-networking`: `all` (default), `internal` (loading only, no page navigation), or `none` (neither). The same levels as the real player's `allowNetworking`.
  - `allow-origins`: the origins that may be reached, separated by spaces (for example, `allow-origins="https://cdn.example https://api.example"`). `*` or omitted means any origin.
  - `credentials`: whether loads send cookies and the like. `same-origin` (default), `omit`, or `include`.
  - `allow-navigation`: `gesture` (default; navigating the page itself only right after a click or a key press) or `always`.
  - `redirect-to` (for testing): a localhost origin such as `http://127.0.0.1:18124`. When set, the destinations of the SWF's loads, media reads, and navigations are switched to
    `/x/<original host>/<path>?<query>` under that origin (the permissions for the original destination are still checked first). Navigation does not move the page; it only sends the same method and
    body. An origin that is not localhost blocks all network access. To read a response to a load, the receiving side must send CORS headers.

  In every case, headers that the real player does not allow (`Cookie`, `Referer`, `Authorization`, and so on) are not sent. SharedObject storage is limited to 100 KB per SWF
  (the real player's default). While the SWF is off screen, it advances only twice per second. To keep the page completely separate, put
  the element inside an `<iframe sandbox>` on a different origin (the script then runs under that page's origin).
- The size is the SWF's stage size (it can be changed with CSS). Mouse movement and buttons are passed on; keys are passed on only while the element has been clicked and is selected.
  Sound plays after the page is first clicked or a key is pressed.
- Events: `trace` (`event.detail` holds the string from `trace()`; when not trusted, also the URL the script requested), `warning`, `error`, and `loaded`.
  `element.movie` is the `Movie` being played. `element.load(bytes, { label })` loads from bytes. `element.stop()` stops it.
- From a script, you can also place one with `import { embed } from './web/flapp.js'; embed(document.body, 'movie.swf', { trust: false })`.

A working example is [web/embed-demo.html](web/embed-demo.html) (use `?swf=` for another SWF, and `&trust` to play it as a trusted SWF).

## Playing in the browser

```bash
npm run serve
```

Open `http://localhost:8123/web/index.html`, then choose a SWF (or FLV) file or drop it on the page.
The server exposes the repository root only to this machine (127.0.0.1).

- Sound plays after the page is first clicked or a key is pressed (a browser restriction).
- For SWF 5 and earlier files, the character encoding can be chosen from a list on the page (it cannot be determined from the file).
- The output of `trace()`, the URLs the script requested, and warnings are shown below the stage.
- When "trust this SWF" is turned on (or `?trust` is added to the URL; without `trust` or with `trust=0`, the SWF is not trusted), the script can navigate the page (`getURL`, `navigateToURL`) and load data (`fetch`).
  The following can be loaded: data for `LoadVars`, `XML`, `loadVariables`, and `URLLoader`; images (JPEG, PNG, and GIF) and SWFs for `loadMovie`, `MovieClipLoader`,
  `loadMovieNum`, and `Loader`; and MP3 for `loadSound` and `Sound.load`. FLV for `NetStream.play` is also taken from http / https in the same way.
  `SharedObject` is stored in the browser's localStorage (per SWF; it is written by `flush()` and when the page is closed, and read the next time it is opened.
  When the SWF is not trusted, values are kept only while it plays). The values that can be stored are numbers, strings, booleans, null, undefined, Date, arrays, and plain objects, up to 100 KB. URLs other than http / https (such as `javascript:`) are not opened.
  Loads from another server work only when that server allows them with CORS. The default is not to trust (do not turn this on for SWFs you do not trust).

## Using it on a smartphone (iPhone and Android)

The playback page, the embedded player (`<flapp-player>`), and the inspector page are made to work on iPhone (Safari) and Android (Chrome) screens.

- **Touch**: a tap is a click, and moving a finger is a drag (they are passed to the SWF as the same input as a mouse). On top of the SWF, finger movement goes to the SWF,
  so the page does not scroll or zoom there (touch outside the SWF to move the page).
- **Display**: when the stage is wider than the screen, it is scaled down to fit the screen width, keeping its aspect ratio. The touched position is converted to stage coordinates.
- **Text input**: tapping an input field shows the on-screen keyboard. Tapping elsewhere closes it.
- **Sound**: it plays after the first tap (a browser restriction).

Not possible: hover (moving the mouse over something without pressing), input with two or more fingers (only the first finger is used), and the right-click menu. SWFs that are controlled with keys
need an external keyboard.

This was checked in a desktop browser set to a smartphone screen size and touch input. It has not yet been checked on real devices (iPhone or Android).

## Building a player with fewer features

You can build a version that leaves out the features you do not use, so less JavaScript is loaded. It is bundled into one file and minified.

```bash
npm run build                    # build every profile into dist/
node tools/build.js flashlite-2  # build the profiles you name
```

Bundling uses [bun](https://bun.sh) (it is not needed just to play; `web/flapp.js` works without bundling).
The usage is the same; only the file you load changes.

```html
<script type="module" src="dist/flapp.flashlite-2.min.js"></script>
<flapp-player src="movie.swf"></flapp-player>
```

| Profile | Left out | Size | gzip |
|---|---|---|---|
| `full` | nothing (the latest Flash Player) | 539 KB | 187 KB |
| `flashplayer-12` | nothing (the same as `full`, within what Flapp implements) | 539 KB | 187 KB |
| `flashplayer-8` | ActionScript 3, LZMA compression, H.264 | 315 KB | 112 KB |
| `flashlite-4` | LZMA compression | 537 KB | 186 KB |
| `flashlite-2` | ActionScript 3, video, LZMA compression, filters, `flash.geom`, `BitmapData` | 229 KB | 81 KB |
| `flashlite-1.1` | the same as `flashlite-2` | 229 KB | 81 KB |
| `no-video` | video | 487 KB | 169 KB |
| `no-avm2` | ActionScript 3 | 318 KB | 114 KB |
| `no-avm2-no-video` | ActionScript 3, video | 267 KB | 95 KB |
| `as3-only` | ActionScript 1 / 2 | 446 KB | 157 KB |
| `animation-only` | ActionScript 1 / 2 / 3, video | 154 KB | 57 KB |

(Sizes are as of 1.1.0. The unbundled `web/flapp.js` is 75 files, 1,212 KB, or 409 KB with gzip.)

- A SWF that needs a feature that was left out plays without it and leaves a warning (the `warning` event). A build without scripts plays only the pictures and sound.
  A build without video does not show embedded video and treats FLV files as not found. A build without LZMA cannot read ZWS files (the `error` event).
- The profiles for Flash Lite and Flash Player versions leave out the features that version does not have (within what Flapp implements). They do not reproduce
  the detailed behavior of that version's player. They have not been compared with a real Flash Lite device.
- The profiles are defined in [tools/profiles.js](tools/profiles.js). The modules that stand in for the features left out are in [src/absent/](src/absent/).

## Viewing the contents of a SWF (SWF inspector)

`web/inspect.html` shows a SWF's header, summary, and list of tags as a table. Selecting a row shows the contents of that tag (its decoded fields and a hex dump of the first 256 bytes).
It only reads the file; it does not run the SWF.

```bash
npm run serve
```

Open `http://127.0.0.1:8123/web/inspect.html` and pass a SWF by choosing a file or by dragging it. A SWF on the same site can be opened by URL, as in
`?src=../test/fixtures/button.swf`.

## Using it from code

```js
import { Movie } from './src/player/movie.js';
import { CanvasRenderer } from './src/render/canvas.js';

const renderer = new CanvasRenderer(canvas);
const movie = await Movie.load(bytes, {
  trace: console.log,
  rasterize: renderer.rasterizer(),
  media: (url) => (url === 'movie.flv' ? flvBytes : null), // the FLV that NetStream.play(url) plays (the player does not fetch it by itself)
  network: { // pass this only when navigation and loading are allowed (decide here which URLs are allowed)
    navigate: ({ url, target, method, data }) => window.open(url, target || '_self'),
    load: async ({ url, method, data, contentType }) => new Uint8Array(await (await fetch(url, { method, body: data })).arrayBuffer()),
  },
});
await renderer.prepare(movie); // decodes bitmaps such as JPEG
setInterval(() => {
  movie.advance(); // advance one frame
  renderer.render(movie);
}, 1000 / movie.frameRate);
```

Input is passed with `movie.mouseMove(x, y)` (in twips), `mouseDown()`, `mouseUp()`, `keyDown(code, ascii, { shift, ctrl, alt })`, and `keyUp(code)`.
Typed characters are passed with `movie.textInput(text)`, separately from the key press (`keyDown`); they go into the focused input field.
For how the browser uses it, see `attachInput` in [web/flapp.js](web/flapp.js). A click moves the focus, and Tab moves to the next input field.
For IME, the string being converted is passed with `movie.compose(text)`; copy, cut, and paste use `copySelection()` / `cutSelection()` / `paste(text)`;
and the mouse wheel uses `mouseWheel(lines)`. The player keeps the caret blinking and scrolling (`scrollV` / `scrollH`).
The options of `Movie.load` are described at `load` in [src/player/movie.js](src/player/movie.js).
Without drawing, Node.js alone can run it (the tests run it this way).

# Notes

- The specification documents that the implementation is based on are in [docs/](docs/) (SWF File Format Specification v19, AVM2 Overview, and Video File Format Specification v10).
- Behavior that the documents do not describe is matched by playing the same SWF in the real player (the debugger version of the Flash Player included with Adobe Animate) and comparing its `trace()` output and screen.
  The real player is used only to check behavior. Its code is not analyzed or ported.
- The real player's output is committed in `test/expected/`, so running the tests alone does not need the real player.
  Regenerating it (`npm run oracle`) requires macOS and the real player.
- Test SWFs are committed in `test/fixtures/`. To rebuild them, besides `npm run fixtures`, you need Java and FFDec for the ActionScript compilers `tools/mkas.js` / `tools/mkas3.js`.
- Some character metrics depend on the device font, so they do not always match the real player. The line height and the baseline use metrics measured on the real player (on macOS with a Japanese environment)
  for each font name: `_sans`, `_serif`, and `_typewriter` are drawn as Helvetica, Times, and Courier (the character widths are measured with the browser's fonts).
- The VP6 decoder ([src/video/vp6.js](src/video/vp6.js)) is a JavaScript port of FFmpeg's decoder, because VP6 has no published specification. That file and the test material generation that depends on it ([tools/mkvp6.js](tools/mkvp6.js))
  are under the same LGPL 2.1 or later as FFmpeg ([LICENSES/LGPL-2.1-or-later.txt](LICENSES/LGPL-2.1-or-later.txt)). The copyright notice is at the top of vp6.js.
- Interlaced VP6 does not show on the real player (embedded video comes out black, and FLV shows nothing), but Flapp decodes it the same way as FFmpeg and shows it.
  Passing `matchPlayer: true` to `Movie.load` (on a browser page, adding `?matchPlayer` to the URL) makes it match the real player.
- When the real player draws embedded H.263 / VP6 video at an integer scale, it blends each pixel's right edge with the pixel to its right, horizontally only.
  Flapp draws without this blend, but with `matchPlayer: true` it blends the same way as the real player.
